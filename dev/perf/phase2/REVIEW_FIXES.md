## Conflicts with the review or the brief (reported, not improvised)

- M1 suggests comparing against `McPost`. `McPost` does not expose the probabilities per site, so the test uses the phase 1
  sampler functions directly (`draw_posterior_hazard_samples_cpp` + `calculate_median_survival_matrix_cpp`,
  `.chunk_ph_sample`), which are the functions `McPost` calls.
- In all HC designs `futility_thr_interim == futility_thr`, and in all PH designs `log_margin_interim == log_margin_final`
  (R23-R28). A swap of those pairs cannot be seen by value. The test separates them by kind and call order instead (interim
  vs final HC are different methods; the final PH pair is `ph_lt` then `ph_ge` on the same inputs). A swap of the two values
  themselves would be behaviorally identical in these designs.
- The test does not check the probability-versus-cutoff decisions (`futility_prob_interim`, `final_success_prob`,
  `final_futility_prob`, `vr_*_prob_*`); the review asked about thresholds and tails only.
- L1: no input in the repo reaches non-convergence, so the stop is tested only through the seam `g_test_force_nonconverged`.
- L2: the brief's "simulators other than run_simulation_pure" is implemented for `run_hybrid_simulations_rcpp` and
  `run_simulation_binary`; direct callers of `run_hybrid_simulations_cpp` get no message. The message also shows up once in
  the existing test "use_cpp_engine = FALSE selects the R body", which is expected.
- Line numbers in REVIEW_phase2.md refer to 3bb0694; they have moved in the current file (e.g. the `ExactPost` call sites
  are now near 801, 829, 1003-1004, 1024, 1028).
- `src/*.o` already exist untracked/ignored in the repo tree from earlier builds; I did not rebuild in place.

### 2.3 run_scenarios, seed handling, worker partition (evolveTrial 58a4850, `R/simulation_driver.R`)

- `unified.R:380-386`: `evolveTrial::run_scenarios(args_i, scenarios, parallel = FALSE, seed = seed, return_variance = TRUE)`. This resolves to the doubly wrapped version (Section 2.1).
- `run_scenarios` (`simulation_driver.R:1268-1272`): `set.seed(seed)` once, then `lapply` over the two scenarios in order (null, then alt) on the SAME master stream (no reseed between scenarios). Args are filtered to the formals of `run_simulation_pure` (`:1287`); no `seed` argument reaches `run_simulation_pure`.
- Inside `run_simulation_pure` (`:~946-1057`): `workers = 19` (`num_workers`, `min(workers, 10000)`); `chunks <- parallel::splitIndices(10000, 19)` (`:976`; chunk sizes 518 x 2, 527 x 12, 528 x 5); `cl <- makeCluster(19, type = "FORK")` (`:1024`); `seed_list <- replicate(19, sample.int(.Machine$integer.max, 1L))` drawn from the master stream (`:1036`); `parallel::parLapply(cl, seq_along(chunks), function(idx, ...) simulate_chunk(chunk_indices[[idx]], seed = seed_vals[[idx]]))` (`:1038-1047`) with `set.seed(seed_vals[[idx]])` inside each worker (`:468-471`). Default RNG kind (Mersenne-Twister, not L'Ecuyer). `aggregate_results(chunk_results)` sums the per-chunk counts in chunk order.
- **Consequence for the acceptance test:** results are a function of (seed, number of workers, order of the two scenarios), not of machine core count. The test must run with 19 workers and the same chunk partition, the same master-stream consumption (one `sample.int` per chunk per scenario), and the same per-chunk `set.seed`. A faster engine that changes the number or order of RNG draws inside a trial, the chunk partition, or the FORK-worker seeding will fail bit identity by construction. Also `num_simulations < 100` runs sequentially (not relevant at R = 10,000).
- P6 option and dropout in `run_simulation_pure`: `looks_stop_at_final` default `getOption("evolveTrial.looks_stop_at_final", FALSE)` (`:236`); `random_dropout` formal (`:271`); `if (!random_dropout) t_random_censor <- Inf` after the uniform draw (`:658`, the draw is consumed so the stream is unchanged).
- Return value and what the wrapper keeps (`unified.R:380-570`): `res_dt` columns per arm and scenario include `Type_I_Error_or_Power, PET_Efficacy, PET_Futility, Pr_Reach_Max_N, Pr_Final_Efficacy, Pr_Final_Futility, Pr_Final_Inconclusive, Exp_N, Exp_Events, Exp_Time` and, with `return_variance = TRUE`, `Var_*` columns (`simulation_driver.R:1062-1115`). `power`/`type1` are the target-arm means over scenarios 2 and 1; `EN_null`/`EN_alt` sum `Exp_N` across arms. The certify rows keep only power, type1, EN_null, EN_alt, weighted_EN_N (see Section 3).

**Precision.** Integer counts (`power_count`, `type1_count`) are exact (the harness stops if a count is not integral, `retune_run.R:409`). `power` and `type1` are count/10,000, exact at 4 decimals. `EN_null`/`EN_alt` are sums of integers divided by 10,000 (so exact at 4 decimals; e.g. 11.247, 71.1824) and `write.csv` keeps 15 significant digits, so nothing is rounded in `rows.csv`. `t1_cert_seeds.csv` shows the same values (E0N 11.247). `weighted_EN_N` is a full-precision double (e.g. 11.2438633333333). One caveat: the Tier 1 readout (`t1_cert_seeds.csv`) omits `weighted_EN_N`, so use the `rows.csv` copies for that column.

**Not stored for these designs:** power-by-look, per-look or per-arm stopping probabilities, `PET_Efficacy`, `PET_Futility`, `Pr_Final_*`, `Exp_Events`, `Exp_Time`, and the variance columns. They are computed inside the simulator (Section 2.3) and discarded by the wrapper's returned vector for the certification rows. Only the older P6 verification files carry PET/futility-timing columns, for the superseded designs: `ATBO/pilot/verify/staged/p6rep_R10k_rows_all.csv` (copy: `docs/reviews/jasa_round1/p6-reported-results/p6rep_R10k_rows_all.csv`, 50 rows = 10 old designs x 5 seeds, evolveTrial 7565a17 with dropout ON, seeds 3025-3029 and 4025-4029). Do not use as a reference for the retuned designs.

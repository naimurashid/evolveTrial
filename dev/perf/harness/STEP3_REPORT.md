## The supported-set predicate

`.chunk_cpp_supported(env)` is TRUE only when every static item holds for the frame and item 11 holds at the time of
the call. The dispatcher evaluates it once per chunk call, in the worker. Each check is wrapped in `tryCatch`, so an
odd configuration counts as unsupported and never errors in `run_simulation_pure`. `.pack_chunk_cfg` returns
`list(supported = FALSE, violations = ...)` outside the set. `simulate_chunk_cpp` re-checks the predicate before
`set.seed`, so a refusal leaves the stream untouched (tested).

## Conflicts between the brief, plan or inventory and the code

- **C1 (inventory 1B and 2.55, brief item 10).** The interim futility threshold comes from a different variable than
  the final one. `args` (SD:377-428) has no `median_pfs_futility_threshold_arms` element, so IL:58's first operand is
  always NULL. The interim futility median threshold is therefore `args$futility_median_arms`, falling back to the
  success vector. The final threshold is the frame's `median_pfs_futility_threshold_arms` (SD:781-782). The inventory
  says the first operand is non-NULL. In all four captures, both scenarios, the two values are `identical()`. The port
  keeps them apart anyway: `cfg$futility_thr_interim` is resolved by IL:57-61 verbatim and `cfg$futility_thr` is used
  at the final. I wrote item 10 to check both resolutions, not to require them equal.
- **C2 (brief item 13).** The brief's list did not name the interim futility probability threshold, `diagnostics`,
  the final probability thresholds, the draw counts, the HC gate shapes or input well-formedness. I pinned these as
  13b to 13g. All of them narrow the set. For 13a I pinned the value itself (unnamed 0), as the brief's "pin it to the
  frozen value" says. Even so, the packed `min_pt_frac` is computed by the package's own `resolve_gate_vec`.
- **C3 (plan "Step 3" shape vs brief).** The plan names `simulate_chunk_cpp(sim_indices, cfg, seed_is_set)`. I
  followed the brief's `(IntegerVector sim_indices, List cfg)`. Rcpp coerces a double `sim_indices` to integer. That
  matches R's `which(sim_indices == sim_idx)` for integral values only. The driver always passes integers. NA indices
  and duplicates follow R's `which` semantics.
- **C4 (brief, gamma sampler refactor).** No refactor was needed. Both existing C++ functions are called directly and
  `posterior_sampling.cpp` is untouched.
- **C5 (gate 2 tooling).** `layer0_seam_check.R` gained an optional 4th argument for the option, as the brief allows.
  Separately, in `cpp_entry_check.R`, a live `run_scenarios` table is not `identical()` to the same table read back
  from RDS, because data.table's `.internal.selfref` external pointer differs. The check therefore round-trips the
  traced result through `saveRDS` before comparing, as the gate files were. This is a tooling detail, not an engine
  difference: `all.equal` was TRUE and `.Random.seed` was identical.

## Open items

- **O1, step 5 (layer 2) blocker.** The certify capture path (`dev/perf/evidence/scripts/capture_cert.R:190-224`,
  copied from `retune_run.R`) wraps `interim_check` with two read-only probes: `verify_m4_install`'s probe and
  `p6r_install(..., "probe")`. Its engine check `eng_ok` requires at least one probe line, and p6r frame values
  `frameF == "6"` and `frameOpt == "TRUE"`, all of which come only from `interim_check` calls. The C++ single-arm path
  never calls `interim_check`, so on R01 to R04 with the C++ engine on that path would report ENGINE FAIL even though
  the numbers are right. The inventory foresaw this at 1C ("A C++ chunk bypasses any such wrapper"). In addition,
  `verify_m4_instrument_install` (Stage A) rewrites `run_simulation_pure` by finding `simulate_chunk <- function` and
  its `for (sim_idx in sim_indices)` loop. It would now find the dispatcher, which has no loop, and stop. I changed
  nothing here. The coordinator decides how layer 2 asserts its environment.
- **O2.** Any other namespace replacement of `interim_check`, `slice_arm_data_at_time`, `draw_posterior_hazard_samples`
  and similar functions is likewise bypassed when the C++ engine runs. Results are unaffected unless the replacement
  changes behavior.
- **Unported:** everything outside the predicate. That covers the between-arm path (step 4), person-time milestones,
  `looks_stop_at_final = FALSE`, dropout on, infinite `max_trial_time`, interim efficacy stopping, the diagnostics
  messages and the progress tick. All of these fall back to the R body through the dispatcher.

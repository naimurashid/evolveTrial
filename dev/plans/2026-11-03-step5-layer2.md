## 1. The environment-check decision (coordinator, 2026-11-03)

**Problem.** The certify call path (`capture_cert.R`, copied from `retune_run.R`) checks its engine from two read-only
probes on `interim_check`: the M4 switch's probe (one line per process, the `random_dropout` the simulating frame holds)
and the P6 protocol's probe (frame F and option values, the build field). The C++ body never calls `interim_check`, so
with the engine on these probes write nothing and the check reports ENGINE FAIL although the numbers are right (step 3
report O1, step 4 report). A second blocker, not in the handoff: the frozen P6 protocol (`p6r_install`, mode p6) and
`capture_cert.R` both refuse a library whose DESCRIPTION lacks `P6RecertEvolveTrialSHA` (and, for `capture_cert.R`,
`VerifyM4PatchMD5`). `lib/dev` is a plain install of the branch and carries neither.

**Decision.**

1. **Library identity.** `build_dev_tree.sh` builds the engine tree from a commit with `git archive` and appends two
   fields. `P6RecertEvolveTrialSHA: 7565a17` states lineage: the script asserts that the commit descends from 7565a17
   and from 58a4850 (the M4 engine of record), and the branch history is 7565a17, 0d5546f, 58a4850, then design and
   port commits only. `EngineCppSHA: <commit>` names the build. `VerifyM4PatchMD5` and `VerifyM4DriverMD5` are not
   written, since the tree is not 7565a17 plus the patch. `layer2_cert.R` in dev mode requires the P6 field,
   `EngineCppSHA` equal to `L2_ENGINE_SHA`, no M4 patch field, and `.simulate_chunk_cpp` in the namespace.
2. **Engine check.** The settings are asserted from what the C++ body received. A read-only wrapper on
   `evolveTrial:::.simulate_chunk_cpp` (installed with `assignInNamespace`, inherited by FORK workers, draws nothing)
   writes one line per call: pid, number of trials, and the packed cfg's `random_dropout`, `min_follow_up_at_final`,
   `looks_stop_at_final` and mode. The dev engine check is the certify check with the two `interim_check` terms replaced:
   - kept: one `run_scenarios` call, M4 switch off and passed FALSE, P6 F 6 and option TRUE (both are `run_scenarios`
     wrappers and still fire);
   - zero M4 probe lines and zero P6 frame events, so no trial ran the R body;
   - C++ trials summed over all processes equal (number of scenarios) x R, so every trial ran the C++ body (a partial
     fallback fails this);
   - cfg values exactly FALSE, 6 and TRUE.
   The reference mode keeps the certify check unchanged.
3. **Stage A instrument.** Not on the layer 2 path. Neither certify runner (`retune_run.R`, `retune2a_run.R`) calls
   `verify_m4_instrument_install`. Only `verify_m4_run.R` and its local test do. Nothing to change.

## 4. Core-hour estimate

Billed core-hours are 19 CPUs times each task's elapsed time. The estimate takes the dev/ref wall ratio measured locally
at 19 workers for each design, applies it to the mean Longleaf reference wall of that design's certify rows (the
Longleaf/local reference ratio is 1.84, the same within 1% for R01 and R23), and adds the measured Slurm startup of the
75 certify jobs (`sacct` elapsed minus wrapper wall, median 4.4 s, mean 4.6 s, max 11.0 s).

| R01 | 5 | 23.2 | 20.7 | 1.12 | 42.8 | 38.1 |
| R02 | 5 | 15.8 | 10.3 | 1.53 | 41.1 | 26.8 |
| R03 | 5 | 16.0 | 8.2 | 1.95 | 25.9 | 13.3 |
| R04 | 5 | 9.9 | 3.8 | 2.58 | 23.3 | 9.0 |
| R23 | 10 | 165.6 | 20.7 | 8.01 | 302.5 | 37.8 |
| R24 | 10 | 56.3 | 2.9 | 19.15 | 104.9 | 5.5 |
| R25 | 10 | 45.9 | 3.0 | 15.42 | 81.9 | 5.3 |
| R26 | 5 | 100.5 | 8.9 | 11.25 | 193.2 | 17.2 |
| R27 | 10 | 37.9 | 2.3 | 16.33 | 70.8 | 4.3 |
| R28 | 10 | 52.2 | 5.2 | 10.01 | 87.5 | 8.7 |

Wrapper wall 1,138 s plus startup 346 s gives **7.8 core-hours**. With every design at its slowest Longleaf reference
wall and the slowest startup, 13.4 core-hours. The dependent gate job adds under 0.01. The 15-minute time limit caps the
array at 356 core-hours if every task hung. The certify runs that produced the reference rows cost 44.6 core-hours.

The plan's 3 to 5 assumed 10x on every design. The single-arm designs gain 1.1x to 2.6x at 19 workers (1.59x for R01 at
1 worker, step 3), and Slurm startup is about a quarter of the total, so the estimate is above that range.

## 5. Review

Independent review (Opus subagent, 2026-11-03), report `dev/perf/layer2/REVIEW_layer2.md`: no critical findings,
1 high, 2 medium, 7 low. No change to the call path outside the tagged list, and no way found for the gate to pass on
vacuous or wrong input. Applied:

- H1. `layer2_stage.sh` installed the engine without the deps library on the library path, so Rcpp and RcppArmadillo
  headers would come from whatever library Longleaf finds. The install now runs with `R_LIBS=$L2_LIB:$L2_DEPS_LIB`.
- M1. The "commit first" guard passed on untracked files. It now uses `git status --porcelain`.
- M2. The gate did not pin the engine commit. `layer2_compare.R` now requires `L2_ENGINE_SHA` and checks every row
  against it. Rechecked locally: right commit passes, a wrong commit and an unset variable fail.
- L1. A row without a mode made the gate stop with an R error. It now gives a clean FAIL.
- L4. The dependent job ran under `/bin/sh` through `--wrap`. It is now `layer2_gate.sh` under bash.

Not applied: L2, L3, L5, L6 (fail-closed or message-only, no wrong-pass path). L7 asks for an "L2-b" tag on the
`mustWork = FALSE` line in `layer2_cert.R`. That line is needed on Longleaf and does not touch the call path. I left the
file as rehearsed so its md5 stays 548fd36ad2bf5e4c87fe3b5a28c5f3b1.
